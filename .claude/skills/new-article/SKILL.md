# יצירת מאמר חדש לאתר AutoSmart

הסקיל מייצר מאמר יחיד, אחיד, לפי התבנית והקול של האתר. עובד מול הריפו
`autosmart-web` (Next.js 16). כל מאמר הוא קובץ `.md` בודד ב-`content/articles/`
עם פרונט-מאטר ותמונת נושא ב-`public/articles/<slug>/cover.svg`.

## כללי ברזל (לא לחרוג)

- **slug עברי בלבד** - שם הקובץ נגזר מהכותרת/הנושא בעברית עם מקפים. לא אנגלית, לא
  תעתיק. `content/articles/<slug עברי>.md`. אין שדה `slug` בפרונט-מאטר - שם הקובץ הוא ה-slug.
- **`date` = היום** - התאריך הנוכחי בפורמט `"YYYY-MM-DD"` (מרכאות חובה), אלא אם
  המשתמש ביקש תאריך אחר במפורש.
- **אנונימיות** - אין שמות אנשים, אין "אני"/"שמי", אין תמונות פנים. המותג נכתב `AutoSmart` (לטינית).
- **תמונות** - אין תמונות של נשים, בשום תמונה באתר. תמונות של פנים/אנשים (גברים)
  מותרות. תמונת הנושא שנוצרת אוטומטית היא וקטורית-גאומטרית (גרדיאנט + רשת קווים
  מופשטת). גם תמונה אמיתית שמחליפים בה מאוחר יותר חייבת לעמוד בכלל - בלי נשים.
- **בלי משפט CTA בסוף הגוף** - הקומפוננטה `ArticleSignature` מוסיפה CTA אוטומטית
  בסוף כל מאמר. לא כותבים `[בואו נדבר](/#contact)` בתוך ה-Markdown.
- **בלי H1 בגוף** - הכותרת מגיעה מ-`title` שבפרונט-מאטר. הגוף מתחיל בפסקת פתיח.
- קרא את `references/voice.md` לפני כתיבת הטקסט.

## פרונט-מאטר (בדיוק השדות האלה)

```yaml
---
title: "<כותרת מלאה, מוטת-תועלת, לרוב דו-חלקית עם נקודתיים>"
date: "<YYYY-MM-DD של היום>"
excerpt: "<1-2 משפטים שמעמידים מתח/הבטחה. משמש כ-meta description>"
category: "<קטגוריה אחת בעברית>"
tags: ["<תגית>", "<תגית>", "<תגית>"]
image: "/articles/<slug>/cover.svg"
---
```

קטגוריות קיימות באתר: `אוטומציה`, `דוחות ונתונים`, `שירות לקוחות`, `אינטגרציה`.
אפשר להוסיף חדשה אם באמת צריך, אבל עדיף לדבוק בקיימות. תגיות: 2-3, בעברית,
ריאליסטיות - הן מזינות את מערכת ה-`/tags` ואת "אולי יעניין אותך גם".

## מבנה הגוף

ראה `templates/article.md`. בקצרה: 1-3 פסקאות פתיח בלי כותרת (כאב מוכר / שאלה
נפוצה / מיתוס) → 2-4 כותרות `##` (לרוב ניסוח של שאלה) → רשימות `-` עם מוביל
מודגש (`**מוביל** - הסבר`), ~3 פריטים → `**bold**` להדגשות. אורך יעד ~250-450 מילים.

## תהליך

1. **`git pull`** (עם `--rebase` אם אפשר). אם יש קונפליקט - לעצור ולהציג למשתמש, לא לפתור לבד.
2. **בירור נושא** - אם המשתמש לא נתן נושא, הצע 2-3 נושאים משירותי הליבה שעדיין לא
   כוסו (בדוק מה קיים ב-`content/articles/` וב-`docs/future-ideas.md`). קבל: נושא,
   זווית, `category`, `tags`.
3. **גזירת slug** עברי מהכותרת. ודא שאין כבר קובץ כזה ב-`content/articles/`.
4. **כתיבת טיוטה** לפי `templates/article.md` ו-`references/voice.md`.
5. **נקודת אישור** - הצג למשתמש את הכותרת, ה-excerpt, ה-slug וגוף המאמר המלא.
   אל תיגע בדיסק לפני אישור מפורש.
6. אחרי אישור:
   - כתוב `content/articles/<slug>.md` (פרונט-מאטר מלא כולל `image` + גוף). CRLF תואם לשאר הקבצים.
   - הרץ:
     `node .claude/skills/new-article/scripts/make-cover.mjs --slug "<slug>" --title "<title>" --category "<category>"`
     → נוצר `public/articles/<slug>/cover.svg`.
7. **אימות מקומי**:
   - `npm run build` - עובר בלי שגיאות TypeScript, `generateStaticParams` תופס את המאמר.
   - `npm run dev` + טעינת `/articles/<slug>` בדפדפן הפנימי - סטטוס 200 (לא 404),
     תמונת נושא + כותרת + תאריך + תגיות + גוף + בלוק חתימה מוצגים. בדוק גם ש-`/articles`
     מציג את הכרטיס החדש עם התמונה.
8. **Git** (כללי CLAUDE.md):
   `git add -A && git commit -m "מאמרים: הוספת מאמר \"<title>\"" && git push`

## החלפת תמונת הנושא בתמונה אמיתית (אופציונלי, מאוחר יותר)

ה-SVG הוא ברירת מחדל. כדי להחליף: שים קובץ אמיתי (למשל `cover.jpg`) תחת
`public/articles/<slug>/`, ועדכן את `image` בפרונט-מאטר לנתיב שלו. הרינדור (עמוד
המאמר, `ArticleCard`, `RelatedArticles`) משתמש ב-`<img>` רגיל - כל פורמט תמונה נתמך.
יחס מומלץ: 1200×630.
